# Word 失败定位及 1.0.3 修复

## 实际记录确认的原因

以只读方式检查了 1.0.2 便携版的任务库，没有打印任务正文、文件内容或密钥，也没有修改原任务。

1. 一条失败记录为 `MODEL_PROTOCOL_ERROR`，原文是“模型未完整结束：length”。该任务记录的输出预留为 8192 tokens，模型以长度限制结束。1.0.2 已经放宽传输字节上限，但长 Word 仍依赖一次完整工具参数生成，未配套处理模型截断。这是额度与生成方式不匹配的问题。
2. 另一条失败记录中 `write_word` 连续两次返回 `INVALID_ARGUMENTS`，具体错误均为参数不是合法 JSON。两次参数约 8.9K 字符：解码到 26 个块后根对象已闭合，后面仍有逗号和约 5.3K 字符；两次错误位置分别在第 3642、3641 列附近。失败发生在工具参数解析阶段，尚未进入 DOCX 写入器。
3. 工程层面的放大因素：正文块和表格没有完整嵌套 schema；参数错误只有泛化提示，未告诉模型出错位置；输入 file_id 的说明也曾被追加到输出文件名参数；工具入口仍留有旧的 64K 参数上限，与上一版公布的 256K 不一致。

不能从这两条记录推断 Office 安装、网络认证或 DOCX 打包失败。记录已经足以说明上述两个触发点，因此没有重放真实用户文稿或调用实际模型服务。

## 修复行为

- 为 OpenAI `length`、Anthropic `max_tokens` 增加独立 `MODEL_OUTPUT_TRUNCATED` 错误。只有尚未向用户输出流式正文时，才在现有模型调用预算内最多恢复两次，要求重新生成较小批次。不会拼接半截 JSON，不提高用户显式配置的模型额度，也不执行截断响应中的工具。
- 当服务返回 usage 时，将失败的截断请求计入 tokens。已经展示的部分流式正文不自动重放；反复截断会明确停止。
- write_word 增加分批草稿参数 `draft_id`、`part_index`、`finalize`。各批次经过校验并在当前任务内持久化，最终由 C# 合成一份 Word。保存草稿不登记成果，不声称完成，最后一批才进行原有成果提交和 output 交付。
- 同批重复提交幂等，不同内容冲突会拒绝；批次必须连续，标题和文件名固定，其他任务不能借用草稿。最多20批内容，索引20允许用空 blocks 完成已有草稿；整体仍受200块、6万字符限制。没有扩张原件编辑权限。
- 补充块类型、文字和二维表格的 schema。JSON 解析拒绝重复键和根对象后的多余内容，并返回行列及小批次建议，不回显正文。入口和宿主外层均传递此反馈，参数上限统一为256K字符。
- file_id 提示只追加到真正的输入引用字段，不再误导输出文件名。

## 模型调用示例

第一批：

```json
{"title":"教案","file_name":"教案.docx","draft_id":"lesson","part_index":0,"finalize":false,"blocks":[{"type":"heading","text":"教学目标"},{"type":"paragraph","text":"第一部分正文"}]}
```

后续批次使用工具返回的 next_part_index，只有完成全部内容后才设置 finalize=true。也可最后提交空 blocks 进行收尾。建议每批不超过12块或2500字，长表格拆成较小段。草稿属于当前任务；失败后的新任务不会自动继承旧任务草稿。

## 验证与交付

新增30项检查，包括普通JSON和SSE截断后实际Host/Worker恢复、非法JSON反馈后的分批生成、无半截文件、重复批次不重复内容、合并顺序、显式收尾、任务隔离、整体限制、截断重试次数、usage统计、可见部分流不重放、只有草稿时不能判成功。
