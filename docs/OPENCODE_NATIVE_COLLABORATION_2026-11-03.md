## 已实现行为

1. 同批最多 4 个子任务可通过 depends_on 引用其他任务名称。完整验证名称、自依赖、重复和环路后才入队，避免错误任务消耗执行资源。
2. 等待依赖发生在获取并发槽之前，倒序链条也不会因占满两个槽而死锁。前置必须处于 Completed；失败、取消或带警告均阻止后续执行，记录 DEPENDENCY_FAILED。无关任务继续运行。
3. 每个子任务现在有独立输入快照，仅复制显式分配的文件。依赖成功后，自动传入摘要，并把该前置的已登记成果复制到后续任务的 inputs/handoff 中。
4. 交接检查父子关系、同轮/同会话、工作区、输出目录、文件大小、最终句柄位置及 SHA-256。复制时源文件保持只读锁定，成果变动则拒绝。新的 file_id 在全部校验及持久化成功后才暴露。
5. 主 Agent 可调用 import_task_artifacts，按 task_id 校验并导入本轮成功子任务成果，再通过已有读取/计算工具处理。原始成果不变，主任务工具的输入映射支持动态更新。
6. manifest.json 记录交接后的输入引用，handoff-*.json 保存源任务、源路径、哈希与新 file_id。依赖任务 ID 和状态存入 SQLite，可通过历史回查；异常中断不自动重放写入。
7. 工作区可配置 allow / ask / deny。子任务继承主任务已经过滤的工具集合和审批要求，配置不能扩展所选技能或只读模式的权限。
8. 并发审批逐个处理，弹窗标明子任务名称与输出范围；每次审批生成唯一请求 ID，过期或已取消请求的迟到回复不能授权下一项操作。用户拒绝时不启动导出 Worker，失败和告警写回主任务。历史对话回放保留子任务开始/结束记录。

## 模型派发协议

```json
{
  "tasks": [
    { "name": "计算", "prompt": "计算分配表格并导出 Excel", "file_ids": ["file_实际引用"], "require_calculation": true },
    { "name": "复核", "prompt": "读取前置成果，检查表头和数值，并列出疑点", "depends_on": ["计算"] }
  ]
}
```

后续任务会收到前置成果的新 file_id，不需要猜测磁盘路径。depends_on 仅引用同批任务；跨批通过主 Agent 导入成果，将返回的 file_id 显式分配给下一批。主模型也可通过 read_task_history 回查完整子任务结果。

自然语言示例：“先让一个子 Agent 分析这份表并导出 Excel，再让另一个子 Agent 读取它的成果复核，最后你汇总。声明好依赖，不要提前执行复核。”具体拆分仍依赖模型正确使用工具。

## 工作区权限

可手工创建 `<工作区>/.claude/xiao.permissions.json`，示例：

```json
{
  "version": 1,
  "tools": {
    "*": "allow",
    "export_xlsx": "ask",
    "apply_file_plan": "deny"
  }
}
```

工具精确名称优先于 `*`，缺省沿用既有权限。deny 的工具不进入模型目录，猜测名称也不能执行；ask 在调用前要求确认；allow 仍不能跳过工具原有审批、技能范围和执行模式。配置格式错误时停止启动任务，不静默放宽。

规则每次 Host 初始化时加载；运行中子任务继承同一父工具权限，不能自行重新读取更宽松规则。只读模式仍沿用现有严格规则，不开放产出或要求审批的工具。此文件由晓助手解析，不代表兼容全部 Claude Code 或 OpenCode 配置语义；不会覆盖它们已有的设置。

## 资源与并发边界

- 每轮总计 4 个子任务、同时执行 2 个；子任务最多 8 次模型编排请求、12 次工具调用、180 秒。主任务 600 秒限时与共享 64 次请求预算保留。
- 单份输入/交接成果最多 10 MiB；单次成果交接最多 20 个文件、50 MiB；每个任务快照累计最多 100 MiB、1000 个引用。
- 子任务只在各自 `outputs/<task_id>/` 生成成果，不共同修改原始输入。尚无多 Agent 编辑同一文件、版本合并或冲突解决功能。
- 不提供子 Agent 直接聊天、递归派发、跨主任务共享状态或崩溃后自动续跑。重复导入会建立新的只读副本，受快照总量限制。
- 数据库事务/WAL、IPC 写入信号量、审批信号量和原子模型预算沿用。仍可能出现数据库锁等待超时、磁盘不足或厂商限流；这些情况不能视为任务成功。
