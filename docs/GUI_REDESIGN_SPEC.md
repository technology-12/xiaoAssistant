# 工作助手 GUI 改版规格

日期：2026-10-31。状态：设计提案，未修改现有 XAML 或 release。

## 1. 目标与依据

将现有开发验证界面调整为面向普通用户的办公助手。参考 ChatGPT 的对话层级和输入体验，以及 WorkBuddy 的任务与成果组织方式；不复制品牌或承诺功能等同。

已阅读 MainWindow.xaml、SettingsWindow.xaml、App.xaml 和 MainViewModel.cs。本次依据源码评估，未启动发布程序进行屏幕验证。

当前问题：
- 三个 GroupBox 等权并列；1024 DIP 宽度扣除左右 500 DIP 后，对话区过窄。
- 顶部 Fake 模式长说明、左侧授权长说明常驻，抢占主要工作区域。
- 对话与系统日志共用等宽字体列表，缺少角色和任务状态层次。
- GUID、SHA-256 等诊断数据位于主流程，用户成果摘要不够突出。
- 默认按钮、文本框与选中态缺乏一致的尺寸、留白和样式。

## 2. 两种布局

### 推荐：对话优先

轻侧栏 + 自适应对话区；成果直接呈现在助手回复中。右侧文件详情抽屉只在用户选择成果后打开。适合现阶段单任务、少量成果的 Demo。

### 备选：成果工作台

侧栏 + 对话区 + 成果预览栏。适合后续经常比较表格、编辑报告的版本。窗口不足 1180 DIP 时将成果栏改为抽屉，不强行挤压对话。

两个方案共享控件和数据模型，不应开发两套业务逻辑。优先落地推荐方案。

## 3. 视觉规范

首期只交付浅色主题；预览可随宿主显示深色，深色属于后续能力。

| Token | 浅色值 | 用途 |
|---|---|---|
| SurfaceMain | #FFFFFF | 主工作区 |
| SurfaceSidebar | #F6F6F4 | 侧栏 |
| SurfaceSubtle | #F4F5F2 | 用户消息、轻选中态 |
| TextPrimary | #262927 | 正文 |
| TextSecondary | #686E69 | 说明 |
| BorderSubtle | #E5E8E3 | 输入框和必要分隔 |
| Accent | #26734D | 状态与图标 |
| ActionPrimary | #283E32 | 发送、保存 |
| ActionForeground | #FFFFFF | 主按钮文字 |
| Error | #B42318 | 错误摘要，须同时包含文字 |

- WPF 单位采用 DIP：基础间距 4，常用 8/12/16/24/32。
- 字体：Segoe UI，中文回退 Microsoft YaHei；正文 14，说明 12，标题 24～28。
- 用户消息 14～15，行高约 1.7；技术日志才使用 Consolas。
- 按钮高 34～36；图标按钮至少 32×32；常规按钮圆角 8，文件卡 12，输入区 18。
- 仅输入区使用非常轻的阴影；避免多层阴影、渐变、玻璃模糊与大面积强调色。
- 图标用随程序打包的 WPF Path/Geometry 资源；不要依赖 Win10/11 才有的图标字体，也不使用 emoji 代替功能图标。
- 系统高对比度启用时改用 SystemColors，保持明确的键盘焦点。

## 4. 布局尺寸

- 保留原生 Windows 标题栏与缩放行为；预览中省略的系统标题栏不等于要求无边框窗口。
- 默认窗口 1180×780 DIP，最小 800×600 DIP。
- 左侧栏默认 224 DIP；主区标题行 60 DIP。
- 对话内容最大宽度 720 DIP，水平居中；左右留白至少 24 DIP。
- 输入区最大宽度 720 DIP，最小高 110，随内容增高至 220 后内部滚动。
- 输入区留在底部，对话内容单独滚动；整个窗口不出现横向滚动条。
- 宽度小于 1000 DIP：侧栏可收起，成果统一用抽屉。
- 小屏或 150% DPI：功能可访问比默认窗口尺寸更优先，按屏幕 WorkingArea 限制启动尺寸。
- 详情抽屉宽 320～400 DIP；窄窗口用模态详情，关闭后焦点回到原文件按钮。

## 5. 主界面内容

### 侧栏

品牌“工作助手”、新建任务、按日期分组的任务历史。底部为当前工作区和设置入口。
历史项展示任务摘要、状态和时间；GUID 在详情中。只展示实际存在的任务，不预填示例历史。

当前 History 只有展示项，未见选中后加载历史记录的命令；历史回看属于本次需要补齐的交互，不能只做可点击外观。

### 顶栏

左侧模型名称与下拉入口，右侧简短模式标识。Fake 在产品文案中称“演示模式”，实际模型称“在线模型”。演示模式始终有可见标识，但移除长黄色条。

模型“已配置”“连接成功”“连接失败”“演示模式”需分开表达；配置了 Key 不代表连接成功。没有接口支持时不显示在线绿点。

### 首次打开

标题“今天，有什么需要帮忙？”，输入框和最多两个真实可用的建议：“汇总销售数据”“生成汇总报告”。建议只填入任务，不直接执行。未授权时显示“选择工作区”，发送不可用并说明原因。

未配置模型时提供“配置模型”或“使用演示模式”。不展示当前并未实现的 PPT、网页检索等入口。

### 对话与执行

- 用户消息使用浅底、右对齐、有限宽度；助手使用无外框正文。
- 工具事件聚合为“正在读取文件”“正在汇总”等自然语言步骤。
- 完成后步骤折叠为“已完成 4 个步骤”；展开可看时间、工具名和状态。
- 系统启动日志不作为助手回复。完整诊断日志通过“执行详情”查看。
- 运行中发送按钮变为停止；显示“正在取消…”直到控制器结束，防止取消后立刻启动新任务。
- 不用假的百分比表示模型推理进度；展示已验证的阶段和不确定等待状态。

### 成果

助手回复下显示文件卡：类型图标、文件名、实际大小、打开动作；“所在目录”“复制路径”“校验信息”在详情中。
SHA-256 不占主界面行；错误文件或不存在的文件显示明确提示。
汇总数据仅从聚合/成果结构读取，不能从模型文本提取数字并伪装成验证结果。若现有层未暴露结构化汇总，首期只显示文件卡与助手文本，不硬编码示例数值。

### 失败与取消

失败显示可读原因与下一动作，例如“无法连接模型，检查接口地址后重试”；错误码和详细日志可展开。
重试创建新的任务，不静默覆盖原成果。重试、恢复草稿均是需要实现并测试的新命令。
取消保留已发生的事件，展示“任务已停止”；符合原设计校验要求的成果才能保留。

## 6. 模型设置

分成“模型连接”和折叠的“高级设置”。

基本项：接口地址（base_url）、模型名称（model）、API Key；字段下显示简短说明与字段级错误。
高级项：超时、系统代理、演示模式。凭据保护、证书说明移到说明区域，不持续占据主窗口。

底部：测试连接、取消、保存。测试时显示等待状态，避免重复提交。对保存与测试分开反馈；测试成功须说明是否检测了工具调用能力。保留现有 SettingsWindow 代码中的控件名与 Click 绑定，或同步重构调用代码。

## 7. 映射到现有工程

| 现有元素 | 新呈现 | 工作量性质 |
|---|---|---|
| FakeMode / ModeText | 顶栏状态＋设置中切换 | 样式与文案；运行中禁用切换 |
| WorkspacePath / ChooseWorkspaceCommand | 侧栏工作区＋输入区目录按钮 | 复用，新增简短目录名属性 |
| UserInput / RunCommand | 圆角多行输入＋发送 | 复用，加输入/授权可用性判断 |
| CancelCommand / IsRunning | 运行态停止按钮 | 复用，加取消中状态 |
| Log | 用户消息、助手消息、工具步骤、诊断分离展示 | 新增类型化展示模型 |
| Artifacts / OpenArtifactCommand | 回复下文件卡 | 复用，补 FileName/SizeText 等展示属性 |
| RevealArtifactCommand | 文件详情动作 | 复用 |
| History | 日期分组侧栏 | 增加 SelectedTask、加载命令和会话切换 |
| StatusText / ConnectionState | 局部任务状态与模型状态 | 复用，补结构化状态而非解析字符串 |
| CurrentTaskId / Sha256 | 详情页中的技术信息 | 复用 |

Presentation 层使用 UserMessage、AssistantMessage、ExecutionGroup、ErrorMessage 类型或明确枚举。不能根据 Log.Display 的中文字符串猜测角色；从事件 Kind、ToolName 和任务状态构建展示模型。不要为了美化而修改 Core、工具协议或文件权限。

WPF 使用 DataTemplateSelector、ItemsControl/ListBox、Border、Grid 和 ResourceDictionary。无 WebView、无新 UI 运行时。保持长对话的 UI 虚拟化，避免 ScrollViewer 包裹 ListBox 破坏虚拟化。

## 8. 实施步骤

1. 建立颜色、字体、间距和按钮/输入框样式，保留现有功能绑定。
2. 改两栏布局、欢迎页、输入区，去除三组 GroupBox 和常驻说明条。
3. 引入类型化对话、步骤折叠、文件卡和详情。
4. 重做设置页，补历史加载、新建任务、草稿和状态交互。
5. Fake 流程验证，再测试真实配置流程；通过后才更新 release，先保留旧版产物。

新建任务只是清空当前展示与草稿，不删除历史或成果；运行中不能切换工作区、模式或当前任务。需要停止当前任务时提供明确操作。

## 9. 验收清单

- 800×600、1024×768、1180×780、1366×768 及 100%/125%/150% DPI 无按钮遮挡、文字重叠。
- 中文长路径、长任务名、长文件名和大量日志可正常换行/省略并查看完整值。
- 所有动作可键盘操作，焦点清晰；输入使用 Ctrl+Enter 发送，Enter 换行。
- 首次使用、未配置、演示、运行、取消中、成功、失败和历史回看均有正确视图。
- 运行时不能重复提交或改变本次任务配置；停止无假成功。
- 预览数字与实际工具结果一致；界面不显示硬编码样例数据或未实现能力。
- 保持已有测试通过，并补充展示状态和历史加载等新增逻辑的验证。
- 在目标 Win7 上验证字体、图标、对比度、窗口缩放和原生标题栏；现代系统截图不替代目标机验收。
