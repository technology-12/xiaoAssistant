# 晓助手 Windows XP 产品基线与迁移方案

日期：2026-11-08；编号：XP-B0；来源版本：1.0.5。当前交付是产品与工程基线、可复现差异审计，**不是已支持 XP 的运行版本**。现有发布包仍是 net48。

## 1. 产品边界

按用户确认，目标同时为 **Windows XP SP3 x86** 和 **Windows XP Professional x64 Edition SP2**。采用 .NET Framework 4 Full、WPF 桌面和本地 C# 内核；保持现有办公与智能体能力。XP Embedded、Itanium 版及未达到各自 Service Pack 要求的系统不在范围内。Microsoft 的 .NET 4 安装包系统要求列有 XP SP3，参见 [官方安装包](https://www.microsoft.com/en-us/download/details.aspx?id=17718)。

XP 版单独维护兼容层和打包入口，与 Win7/现代系统主线并行。不能通过修改 supportedOS、exe 名称、安装器判断或把 net48 的程序集拷进去来证明兼容。最终所有可执行入口、Worker、第三方托管与原生依赖必须符合 XP 基线。

| 必须保留 | XP 版实现约束 |
|---|---|
| 本地智能体 | 计划、工具循环、错误恢复、队列与状态机仍在本机 |
| 并发子 Agent | 默认最多 2 个并发；独立上下文，可读写，保留依赖、取消、写入协调与审批 |
| 上下文压缩 | 保留当前目标、文件状态、工具恢复点和最近对话，原始消息可回查 |
| 三档权限 | 请求批准、帮我批准、完全访问；任务快照和子任务继承；deny/只读约束优先 |
| 办公自动化 | 本地 DOCX/PPTX/XLSX 读写、PDF 文本提取、分段写入与检查点恢复 |
| 技能 | 默认技能、Skill Creator 与按需读取；执行脚本必须符合 XP 依赖清单 |
| 交互与工作区 | 项目管理、自动找文件、内联卡片、完整滚动、成果打开链接 |
| 干净便携交付 | 独立用户数据、无开发者历史；根目录只有原要求的四个文件和文件夹 |

仅模型计算允许外部 API。不能将“XP 远程桌面连接新版客户端”或“远程服务器运行完整内核”作为本基线的替代实现。

## 2. 已确认的代码差异

运行 `scripts/Audit-WindowsXpBaseline.py` 可得到准确到文件与行的审计，以及来源文件 SHA-256。报告不输出源代码片段、模型凭据或用户历史。规则采用词法匹配，数量代表匹配行，不代表独立故障数，也不是完整 API 清单。

| 范围 | 当前实现 | 迁移方向 |
|---|---|---|
| 构建 | 全局 net48、WPF、多个进程入口 | 独立 net40/x86 与 net40/x64 工程配置；真实 4.0 引用程序集；所有入口统一校验 |
| Core | IReadOnlyList、Task.Run/WhenAll、异步取消、异步延续选项 | 改接口或提供隔离兼容层；保持取消、调度与异常传播语义 |
| 并发工具上下文 | DocumentLimits 使用 AsyncLocal | 设计随逻辑执行上下文传递的代理隔离容器，不能换 ThreadStatic |
| 模型 HTTP | HttpClient、SSE、重试与取消 | 可注入的 XP 传输层，保留两种模型协议、流式解析和诊断 |
| Worker IPC | 异步管道及 GetNamedPipeClientProcessId | XP 管道适配、认证和进程退出控制；身份校验失败须拒绝执行 |
| 文件事务 | GetFinalPathNameByHandle、SetFileInformationByHandle | 重做路径边界验证和提交协议，不可删除校验来换取可运行 |
| Office | ZipArchive 与压缩程序集 | 可替换的受限 ZIP/OPC 访问层；保持大小、解压比、路径限制 |
| CSV/PDF | CsvHelper 33.0.1、PdfPig 0.1.9 | 当前缓存无 net40 资产；评估源码移植或替换实现，需协议/许可证与回归验证 |
| JSON | Newtonsoft.Json 13.0.3 | 已有 net40 资产，可作为候选；不是直接判为不兼容 |
| SQLite | System.Data.SQLite 1.0.119 | 元包与托管目标不证明 native 可用；分别检查 x86/x64 SQLite.Interop、进程位数及 CRT/WinAPI |
| WPF | 新版滚动属性、字体与渲染依赖 | 使用 4.0 可用属性；低配置软件渲染、中文字体回退与高 DPI 验证 |
| 打包 | net48 环境准备和依赖 | XP 独立安装检查、.NET4 Full 准备流程、x86/x64 原生依赖及最终 PE 审计 |

命名管道客户端 PID 接口最低为 Vista，参见 [Microsoft API 要求](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeclientprocessid)。文件句柄最终路径接口也要求 Vista，参见 [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)。Job Object 不能整体判为 XP 不支持，需逐项核对所用标志、结构布局和父子进程行为。

现代 C# 编译器能生成部分旧运行时可用的 IL，但不能让新框架 API 自动存在。`async/await`、元组、编译器生成属性和包中的隐含运行时依赖，都必须通过真实 net40 引用集构建和运行核实。禁止使用安装在开发机上的 4.8 程序集充当 4.0 引用集。

## 3. 工程落地结构

### 双平台构建和交付约束

XP x64 的目标 Service Pack 按 SP2 单独定义，参见 [Microsoft 的 XP Professional x64 SP2 下载说明](https://www.microsoft.com/en-us/download/details.aspx?id=18242)。不能用 32 位系统的 SP3 检查逻辑判断 x64 系统是否合格。

| 目标 | 构建 | 拟定 PE 子系统版本 | 候选包标识 |
|---|---|---|---|
| XP SP3 32 位 | net40 / x86 | 5.01 | windows-xp-x86 |
| XP Professional x64 SP2 | net40 / x64 | 5.02 | windows-xp-x64 |

PE 版本只是构建约束，不能证明系统 API 与依赖兼容。禁止以 AnyCPU 自动选择进程位数；Launcher、Host、Worker 和 SQLite 等原生依赖按目标配套。x64 需验证 IntPtr/结构体大小、句柄传递、P/Invoke 对齐、注册表视图、运行时安装检测与本地进程身份检查。两平台同等保留全部必需能力，模型传输/TLS 依赖也要分别审查。

用户数据保持兼容的数据格式，但每个验收用例使用独立目录，不让两个版本同时写入同一个测试数据库。若未来声明 x86 包也可在 XP x64 的 WOW64 中运行，必须补充第三套运行证据；不能用该声明替代原生 x64 包的验收。

下方 XP-01 至 XP-10 的工作包均覆盖两个目标，交付记录必须明确列出各平台结果。只有一个平台通过时只能标注该平台的阶段结果，完整双平台基线仍不得放行。

```text

scripts/Audit-WindowsXpBaseline.py  来源指纹与差异扫描（本轮已实现）
src-xp/                     下一阶段新增，尚未实现
  Directory.Build.props     net40、显式 x86/x64 配置、分别输出
  Xiao.Xp.sln               独立解决方案
  WorkAssistant.Compatibility.Xp/  调度、上下文、网络、文件/IPC、归档适配
  WorkAssistant.*.Xp/       Launcher、Desktop、Core、Host、Infrastructure、Tools
installer/xp/               XP 独立环境检查与运行环境准备，待实现
```

构建仍在现代开发机运行，不要求 XP 安装 SDK、Python、Node 或 Git。优先链接可共享源文件，仅对无法保持语义的模块建立明确适配接口；避免整套长期复制后两条产品线各自修复。每个链接源文件需要同时经过主线与 XP 编译。兼容接口先放在 XP 独立工程，待语义稳定后再决定是否上提主线，不能为了多目标编译污染所有业务调用。

拟定接口职责（是设计契约，当前尚未声明这些接口）：

| 接口 | 责任与不变量 |
|---|---|
| IXpTaskScheduler / IAgentExecutionScope | 逻辑上下文、异步锁、超时与延续调度；不同 Agent 的令牌、工具名与检查点不串扰 |
| IModelTransport | POST/SSE、流式 UTF-8、取消、限制、超时、错误分类；不含工具执行权限 |
| IWorkerTransport / IWorkerIdentityVerifier | 当前会话身份、随机实例与启动凭据、消息帧上限、启动超时与退出清理 |
| IVerifiedFileSystem / IAtomicDocumentCommit | 工作区边界、重解析点/硬链接策略、修改前复核、锁、临时文件与原子提交/恢复 |
| IOfficePackage | ZIP/OPC 安全读写、relationship 和媒体检查、受限解压、文档校验 |
| ILocalStateStore | 会话/任务原子更新、并发协调、损坏恢复、权限快照及迁移 |

## 4. 联网方案

XP 原生网络栈与现代模型服务的 HTTPS 能力不能视为兼容。Microsoft 说明 TLS 1.2 的 Schannel 支持始于 Windows 7/Server 2008 R2，参见 [SSPI 架构](https://learn.microsoft.com/en-us/windows-server/security/windows-authentication/security-support-provider-interface-architecture)。仅设置 `SecurityProtocol=3072` 无法给 XP 添加对应实现。

提供两个可验证方向：

1. **指定 IP/域名的模型接口或仅转发模型的网关**：推荐的首个联通方案。现代机器负责与模型厂商的 TLS；XP 仍负责所有智能体与文件操作。网关支持所选 OpenAI/Anthropic 协议和 SSE，不要求上传工作区或文档目录。提供网关专用访问令牌，优先将厂商密钥留在网关。HTTP 只能在用户明确配置的可信局域网/受保护通道使用；不自动从 HTTPS 降级，不在公共网络直接暴露厂商密钥。
2. **XP 本机直接现代 HTTPS**：单独选择并验证仍能在 XP 运行的 TLS 实现、证书链、域名/SNI、随机数和吊销策略，完成依赖、许可证及安全评估后才能默认开放。当前没有选定或交付该依赖。不能预先承诺直接连接 DeepSeek 等公共端点必然可用。

流式传输必须保留已有“模型未完整结束”恢复策略、响应长度边界、usage、reasoning_content、预算核算、有限续写和取消能力。不得以完整缓存任意大小响应解决 XP 网络兼容。不能用忽略证书验证解决连接失败。

## 5. 文件、并发和权限适配约束

XP 没有部分现用句柄 API，首先要把安全不变量写成用例，再确定适配实现。普通字符串路径归一化不能替代最终对象校验。受控工作目录、拒绝重解析点、提交前复核文件身份与共享模式、同卷事务日志/重命名是评估方向，不是已被证明安全的实现。不能实现等价边界时，明确拒绝该操作并保持发布门槛阻塞。

管道随机名、当前 SID ACL、一次性启动凭据、宿主对子进程生命周期绑定可组合设计 XP 认证，但仅靠“收到的 PID 相同”或“管道名随机”不能视为完整身份验证；要验证抢先连接、重放、同用户干扰、进程提前退出及句柄继承泄漏。

异步兼容层禁止直接将 RunContinuationsAsynchronously 改成 None；否则审批和写锁释放路径可能内联重入。AsyncLocal 替代物必须在工作迁移与逻辑上下文复制中保持隔离，ThreadStatic 不符合要求。共享文件写入继续采用规范化资源键、任务/操作标识、互斥与提交前版本检查；子任务不能绕过父任务权限。全访问仍受工作区限制、显式 deny 和只读角色约束。

## 7. XP 实机或虚拟机验收矩阵

必须分别准备真实运行 XP SP3 x86 与 XP Professional x64 SP2 的验收机，均安装 .NET 4 Full，不能仅用 Win10 兼容模式或只在一个系统运行。安装适用更新并记录实际补丁清单。发布证据记录 OS、CLR、位数、安装的运行时与原生依赖、模型接入方式、样例数据散列、候选二进制散列及测试日志。

- 启动：干净用户、普通权限、中文/空格路径，首次准备环境；已安装 .NET4 时可直接运行；不要求 Python/Node/现代 PowerShell。清楚区分 Full 与 Client Profile。
- 模型：指定端点的鉴权、OpenAI 与 Anthropic、正常/异常 SSE、401/429/5xx、取消、断网和恢复、模型长度截断；所声称支持的接入模式都要在 XP 实测。
- 智能体：多轮工具、上下文压缩后继续任务与原文回查、任务重启、子 Agent 依赖与结果交接；两个可写子任务同时修改同一文件不能静默覆盖。
- 权限：三档模式、排队期间模式变更、权限快照、子任务继承、显式 deny、只读角色及审批中断；禁止借兼容层绕过原策略。
- 文档：1/5/10 个 Word 批处理、至少 8 万字 Word 分段写入和 45 页 PPT、Excel 公式/格式、中文 PDF 提取；记录内存和耗时，输出必须可校验与打开。取消、失败、重启后检查点恢复不重复提交。
- 边界：ZIP 炸弹与路径穿越、外部 relationship、输出重名、工作区外链接、进程抢连、并发替换、磁盘满/只读、中文长文件名；拒绝场景有清晰提示且不损坏已有文件。
- 界面：1024×768 与高 DPI，长消息滚动到底、输入提示不重叠、Enter/Shift+Enter、内联问答与批准卡片、项目编辑/删除保留文件、成果直接打开；低性能渲染不长时间阻塞 UI。
- 交付：根文件 `晓助手.exe`、`检查运行环境.cmd`、`准备运行环境.cmd`、`首次使用说明.txt`，依赖收进文件夹；不含聊天数据库、临时文件、日志、开发者设置。默认模型凭据沿用既定发行政策，但不能复制开发机个人设置；调试和审计报告不含密钥。

性能指标先在上述 2 GB 验收机建立实测表，再设可执行阈值。不能凭开发机速度承诺 XP 上的并发和大文档性能；如果内存不足，先采用限流、分段与背压，不直接取消功能。

## 8. 发布判定与后续入口

`baseline.json` 的 `release_ready` 当前为 false；两个目标各 9 项发布门槛，共 18 项，尚无验收证据；不能用一个平台的通过记录替代另一个平台。审计器 `--check` 故意返回 2，不存在“零词法匹配自动通过”的路径。需要后续增加构建、依赖、安全和真实 XP 运行证据校验后才能实现发布放行。

当前没有 XP 二进制和 XP 安装包，也没有经过验证的直连公共 HTTPS 方案。现有 1.0.5 的验证数量不能计入 XP 验收。后续第一项明确动作是 XP-01，而不是修改现有发布包名称或向用户分发未经验证的 XP 版。
