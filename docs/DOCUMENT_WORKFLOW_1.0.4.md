# 晓助手 1.0.4：文档可靠性更新

## 修复内容

- 截断恢复：JSON、SSE 与 Messages 的输出长度结束被单独识别；不执行本响应工具。保留已显示内容并继续，连续两次恢复仍截断才停止，正常步骤打断连续计数。失败调用的 usage 也计入统计。
- 网络恢复：显示文字后发生连接中断，保留片段，受控继续剩余工作；不把片段当作完成，不重放工具。
- 工具纠错：保留语法位置和具体错误，连续错误时提示改变策略；连续四次参数错误无进展才停止，相同调用循环保护继续有效。
- 供应商适配：保存并回传 Chat Completions 的 reasoning_content，解析思考 token 用量；遵循 DeepSeek 思考模式工具调用协议。只对官方端点及已核实的默认模型应用能力默认值，不推测第三方 IP 网关能力。
- 默认额度：官方 DeepSeek 两个默认模型采用100万上下文与32768单次输出预算；32K是应用选择，低于供应商最大能力。显式配置优先，其余端点沿用配置/工作区模型目录。
- 长上下文：大模型窗口也受本机软阈值触发压缩；过大的工具结果保存在本地步骤记录，以回查引用进入上下文。摘要生成截断会缩小整理范围并受控重试，原始消息保留。
- 任务预算：普通任务默认最多128次模型编排请求、256次工具调用、30分钟；主/子任务共享编排上限256次。用户显式角色与子任务预算仍可收紧。
- 办公技能：默认Word/PPT相关技能接入 document_workspace，保持既有权限、输入快照与审批边界；子任务可使用父任务实际允许的办公工具，各任务输出仍隔离。

## 本地文档工作台

`document_workspace` 支持以下动作：

| 动作 | 行为 |
|---|---|
| plan | 登记本轮所有预期成果文件名，避免只完成一份就报告全部完成 |
| begin | 宿主生成文档ID，同任务文件名保持稳定身份 |
| append | 按章节追加Word正文块或PPT页面，返回章节ID和版本 |
| patch | 根据章节ID、章节版本和稳定操作ID更新局部内容 |
| inspect | 分页回读本地章节与内容，返回文档/章节版本 |
| finalize | 按最新文档版本合成文件，回读正文/表格/页数/讲稿后交付 |
| status | 查询待交付成果、草稿版本和输入阅读覆盖 |
| resume | 将当前会话有权回查的历史草稿复制到本任务，不修改来源任务 |

新流程的元数据与不可变章节版本位于工作区 `.claude/outputs/<task_id>/`；只有最终验证后的成果登记并发布到 `output`。模型只接收小批内容及状态，用户不需要操作草稿ID或手动拆分原稿。

每次 append/patch 使用稳定 operation_id；重复同一操作不会追加两次，同ID换内容被拒绝。章节校验值、版本校验、按任务锁和跨任务恢复的有序锁避免并发覆盖。新版本保留旧内部文件；同一逻辑文件的旧成果从当前交付清单中移除，另起文件名创建的独立稿件仍作为独立成果保留。

旧 write_word 的 draft_id/part_index/finalize 保持兼容，草稿由最多20批改为受资源预算约束的最多2000批；中间批次只校验结构，不反复打包整份DOCX。resume 可用 legacy_draft_id 导入同会话的1.0.3草稿。恢复是复制到新任务继续，不能跨会话借用草稿，也不是在软件启动时自动重放未确定的写入。

Word/PPT编辑工具新增 artifact_name，可在当前任务内校订自己的输出，不再把成果路径误作输入 file_id。同名不同内容的修订创建内部版本，不覆盖原始文件。

## 阅读与完成验收

read_document_text、inspect_office 对超长行/段落返回片段及 next_line/next_item/next_char，不再要求用户先拆段。输入仍通过不可变快照和 file_id 访问。

分页范围记录在本地，不因压缩历史丢失。明确要求通读、逐段或全文校对时，宿主登记目标文件的全文阅读要求；读取最后一页不能掩盖中间空缺。完整覆盖和所有必需文档完成之前，模型的口头“完成”会被拦截并要求继续。

这是正文覆盖与结构验收，不能代替事实核查、内容质量评价或实际页面渲染；图片文字、SmartArt、复杂图表和扫描PDF不在普通文本覆盖内。

## 资源配置

单次响应与整份文档资源分开管理。默认整份Word最多100万字符、1万块，PPT最多200页；旧版6万字符、200块不再作为普通长文档门槛。单次工具参数仍为256K字符；工作台每批至多100块/页、5万JSON字符，建议实际调用更小。草稿默认800万JSON字符，章节2000个，操作记录4096条；仍有解压大小、内存、处理时间和任务总预算。

可创建工作区 `.claude/document-limits.json`：

```json
{
  "max_document_chars": 1000000,
  "max_blocks": 10000,
  "max_slides": 200,
  "max_draft_chars": 8000000
}
```

可配置上界分别为200万字符、2万块、300页、1600万草稿JSON字符；提高配置不能绕过包大小、解压和执行时限。草稿超过预算时保留此前已保存内容并说明原因。

## 验证与边界

最终候选的测试清单、计数和二进制校验值写入包内 `verification/summary.json`。包含本地发布诊断、JSON/SSE模拟API的实际Host/Worker链路，以及新增工作流测试。

新增用例覆盖30批/360块/8万字符以上Word、45页PPT、项目符号/表格/换行回读、章节修改与旧操作幂等、并发重复写入、草稿完整性、受限恢复、全文阅读空缺、显示文字后截断与断流、思考字段往返、较大工具结果归档与摘要截断恢复。

真实DeepSeek测试仅发送合成小学科学教案，分别请求1、5、10份、每份约300字，检查必需成果、正文、哈希及output发布；报告记录实际字数。模型可能生成另名的补充稿件，验收要求全部指定稿件存在，不把合理附加稿件数量当成协议错误。这不能等同于“真实模型已经生成单份8万字”：8万字符和45页PPT来自本地工作流压力测试。未向模型发送用户原稿。

仓库早期控制台全量用例还含过时路径/预算断言及环境依赖，其原始失败输出保留于 artifacts/diagnostics/document-workflow/console-result.txt，未作为本次发布的通过项。本次通过项以实际重跑的发布诊断与新增用例为准，不沿用旧包测试数字。

便携包保持根目录四个普通文件：晓助手.exe、检查运行环境.cmd、准备运行环境.cmd、首次使用说明.txt，其余内容在“程序文件”。不含聊天数据库、任务草稿、测试原稿或使用后的用户数据。首次运行建立独立“用户数据”。

仍需 .NET Framework 4.8；免安装指应用本身，缺少运行库时使用随包环境准备工具。Win7 SP1实机、全新机器安装运行库及Office/WPS实际页面渲染仍未验收；本包应用程序未签名。
