# 晓助手 1.0.1 使用体验修复

本版覆盖用户提出的六项问题，同时将便携包启动 EXE 放到解压根目录。

| 问题 | 实现行为 |
|---|---|
| 工作目录难辨认 | 首次使用创建“文档\晓助手工作区”，输入区下方显示完整实际路径，并提供“打开目录”“输出文件”按钮；用户仍可更换目录。 |
| 输入提示重叠 | 提示直接绑定输入控件的实际文本与焦点；任何文字（包括空格）出现后隐藏，获得输入焦点时也隐藏，清空并失焦后恢复。 |
| 便携版出现旧聊天 | 上个 ZIP 未带聊天数据库，但程序读取了本机共用 AppData。本版检测 portable.mode，设置、任务库、自定义技能与连接设置使用本发行目录的“用户数据”，不自动读取旧目录。打包排除该目录。 |
| 文档藏在长任务目录 | 用户成果直接交付到工作区 output 根目录；不同内容的同名文件按“文件名 (2).docx”等编号，保留原文件与用户修改。内部隔离成果转入 .claude/outputs/任务ID，继续用于验证、恢复和子任务交接。 |
| 缺少直观的预览/打开入口 | 对话文件卡直接显示文件名链接、“预览”“打开文件”“详情”；文件卡使用交付副本路径。预览只读取已登记且摘要一致的成果。 |
| 长回复滚不到底 | 虚拟化列表改为像素滚动，并约束内容宽度。单条超长消息可以滚动到最后一行；用户上翻后新文本不抢位置，回到底部后恢复跟随。 |

## 便携包

`artifacts/packages/XiaoAssistant-1.0.1-portable.zip`

完整解压后直接双击同层的“晓助手.exe”。不再需要寻找 app 子目录。应用程序集名称仍为 WorkAssistant.Desktop，分发入口改为晓助手.exe，并同步配置文件名，Host、依赖、本机组件、技能和默认模型配置均随包。

缺少 .NET Framework 4.8 时运行“准备运行环境.cmd”，使用附带的微软官方离线运行库安装器；运行库安装可能需要管理员权限。已有兼容运行库时直接启动 EXE。应用构建未签名，Win7 SP1 实机验收仍待目标环境执行。

用户数据不会与旧版共享，也不自动删除旧记录。重新分享软件请发送原始 ZIP；使用过的解压目录会包含用户自己的记录。工作文件默认保存在“文档”，不随删除发行目录而删除；用户仍应正常备份工作区。

## 工程细节

- ApplicationDataPaths 统一便携/安装版数据根。普通安装版未出现 portable.mode 时保持原 AppData 位置。便携版单实例互斥锁按数据根区分，避免误关联本机已运行的旧版。
- ArtifactInfo.PublishedPath 单独持久化交付地址；内部 Path 继续记录确切来源，模型回读和跨任务授权不依据公开目录猜测。父任务只能发布自身或明确记录的子任务交接成果。
- ArtifactDelivery 在校验字节数与 SHA256 后复制到临时文件、刷盘，再通过句柄原子改名提交。拒绝目录链接和路径越界，不覆盖目标；并发撞名重试版本编号，重复交付可复用同摘要文件。
- 新任务内部路径为 .claude/outputs；已经存在的旧 outputs/任务ID 保持可读，未批量搬动或删除旧成果。
- VerifiedFiles 的 FILE_RENAME_INFO 缓冲增加显式 WCHAR 终止符，以确定的 NUL 终止名称传入 Win32 API；中文交付测试覆盖此路径。
- 发布副本失败时保留内部成果，并将任务标为带告警完成，提示目录权限或磁盘问题，不伪装成已经成功交付。
- Word/PPT 预览是文字/表格内容预览，不是页面或幻灯片视觉渲染。用户编辑过交付副本后，摘要变化会阻止按旧摘要预览，仍可在本地应用打开。

## 验证

新增 38 项专项检查，覆盖中文文件、并发撞名、用户改动保留、父子归属、持久化、实际模型 Host 的 Word/PPT 平铺交付与 IPC 预览、输入提示、800×600 长消息到底和流式滚动位置。全部使用隔离数据与本地模拟模型。

此前 426 项检查继续用于回归；个别检查中的旧内部输出路径随目录变更更新，仍检查原有权限、审批、恢复和协同语义。候选包 verification 保存本次记录；实际解压换路径、EXE 重命名与干净用户数据的发行验证另保留在同名 validation.json 中。

不把本机测试计为另一台 Win7 的实机验证，也未在开发主机安装附带运行库或使用真实模型 Key 进行测试。
