# 晓助手：20 轮内核迁移路线图

日期：2026-11-04。当前已交付第 1～7 轮候选，第 8 轮起为实施计划。第七轮按用户最新要求改为办公文档自动化；原项目树阅读保留为第八轮前置工作包，未标为完成。20 轮包含已完成轮次，不是再增加 20 轮，也不是工期承诺。

## 完成目标与边界

以固定的 OpenCode v1.1.20 / `09ff3b9bb925903b36aa35fec25394133a42cf6d` 为对齐基线，在第 20 轮形成可发布的本地 C# 内核：具备办公文档、项目阅读、受控编辑、终端、多 Agent 协作、恢复、Skill/Command、MCP、语言服务、多模型协议及桌面操作闭环。新闻稿、教案和演示文稿属于产品主场景，不仅服务研发。模型计算可访问配置的厂商 API；任务编排、文件和命令执行、权限、数据存储都在本机。

迁移以行为、协议、错误与恢复语义为验收对象。保持 WPF/.NET 4.8/Win7 目标，不把 TypeScript/Bun 源码复制到工程当作功能完成，不追求用无效代码凑到十万行。参考源码不计入自研规模。MIT 来源与改动说明随交付保留。

“第 20 轮完成”指本文件锁定的目标通过验收，不表示与上游所有平台、每个第三方 SDK、托管分享服务或 TUI 外观逐字节等价。全量对齐矩阵持续记录未覆盖分支。Win7 无法使用的系统能力要有实测可行的替代路径；不能仅标成“不支持”就算完成一个核心能力。

路线图是收敛目标，不是预先保证所有未知协议和实机问题均能在固定轮数解决。发现阻塞时调整每轮工作包；不能把未完成项换名、删除后宣称全量迁移完成。第 20 轮仍未通过的必需项目必须保持未验收状态。

## 四个里程碑

- 第 8 轮：可阅读授权文件并可靠生成/提交变更；支持多文件版本冲突处理。此时仍需第 9 轮终端支持，不能宣称具备完整编码 Agent 能力。
- 第 12 轮：本地终端、恢复、多 Agent 和 Git 协作闭环，可承担较完整的本地研发任务。
- 第 16 轮：Skill/插件、MCP、语言服务和主要新模型协议打通，接近成熟 Agent 内核的主干能力。
- 第 20 轮：固定范围内完成发布验收；保留与完整上游生态的差异说明。

## 各轮共同交付约定

每轮提供源码、独立 `artifacts/iterationN-candidate`、本轮设计/变更/差异说明、可复现验证与报告。旧候选保留便于回归。只有通过行为检查才更新“已交付候选”；Win7、真实 API 和发行验收另列，不随构建自动变为已通过。

每轮至少验证本轮主要正常路径、权限拒绝、取消或故障、持久化及恢复边界，并回归受影响的旧链路。涉及写入必须覆盖基线变化、重复调用和进程丢失；涉及并发必须覆盖同资源冲突；涉及模型协议必须覆盖真实 HTTP/SSE 结构和不完整响应。

每轮更新全量矩阵和本表。新增需求优先落入已有工作包；确有必要新增轮次时说明原因，不提前许诺绝对兼容。主内核完成前不把工作量转移为纯 UI 改名或代码规模扩张。

## 第五、六轮完成情况与后续入口

第五轮已实现 `plan_text_edit` 和 `validate_text_edit`。提案保存原始/候选字节、SHA-256、理由、匹配数量、diff 与提案指纹；与移动计划共用任务级持久计划存储，但严格检查计划类型，旧 apply_file_plan 不能执行文本提案。文件保持 inputs 范围，尚未扩大到整个项目源码树。

第六轮已增加独立 apply_text_edit/rollback_text_edit，不复用移动工具。审批展示源路径、基线、指纹和完整差异；在 NTFS 事务中复验、更新、提交，并保存备份、意图和回执。不可用卷拒绝提交，不普通覆盖降级。回滚仅限本任务计划且绑定当前输出版本，不能覆盖后续修改。只读角色、规划模式及子任务作用域继续生效。详见第六轮说明中的平台支持及实机验收边界。

第七轮按用户要求完成基础办公文档链路，补齐新闻稿、教案、PPT 的实际文件工具。原项目树阅读与多文件变更仍待第八轮，第 10/12 轮推进会话/Git 级撤销。办公扩展不替代这些未完成的工程能力；后续同时保留复杂文档/自动渲染的需求，不再将产品仅定位为研发助手。
