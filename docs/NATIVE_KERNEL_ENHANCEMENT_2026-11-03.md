# 晓助手：本机 C# 内核增强与交接

## 运行路线

采用 C# / .NET Framework 4.8 本机内核，目标继续覆盖 Win7 SP1。任务编排、文档解析、工具执行和状态保存在用户电脑；模型仍可连接 DeepSeek、公网 API 或指定 IP 的兼容模型服务。

新入口：`artifacts/native-candidate/WorkAssistant.Desktop.exe`。使用完整文件夹，先退出旧版及托盘实例，然后直接双击程序。无需 Node.js、Bun、OpenCode 可执行程序、单独网关或服务令牌。Win7 仍需安装 .NET Framework 4.8；本轮没有 Win7 真机验证。

`config/kernel.policy.json` 随包复制并固定 `ForceLocalKernel=true`，优先于旧远程连接文件；即使旧文件启用了远程模式、密钥不可解密或内容损坏，也不会影响本机模式启动。旧配置未被删除或改写。设置页隐藏旧远程配置，底部显示“本机 C# 增强内核”。

旧迁移工程及候选目录保留作为参考。包中可保留名为 `WorkAssistant.OpenCode.dll` 的 C# 配置/适配程序集，其存在不表示启动 OpenCode 运行时。

参考已下载的官方 OpenCode v1.1.20 源码，尤其是 `session/compaction.ts`、`session/processor.ts` 和工具组织方式，进行独立 C# 实现，没有复制 Bun/TypeScript 运行环境。

| 能力 | 当前行为 |
|---|---|
| 长对话摘要 | 接近本机字符预算时，请求同一配置模型整理较早上下文，保留当前目标和近期完整工具消息组 |
| 原始记录回查 | 按当前会话中的任务 ID 分页读取原始步骤、消息、成果、摘要或输入快照清单 |
| 内部任务计划 | 保存步骤、状态和 revision；后续 Worker 调用可继续更新，防止旧版本计划覆盖新进度 |
| 文档阅读 | Word 正文/表格段落、文本型 PDF、TXT/MD/JSON/LOG/XML/CSV 的按行分页读取 |
| 内容搜索 | 最多 10 个授权文档的字面文本搜索，返回文件引用、行号、列号和片段 |
| 按需技能 | 模型按需列出技能并读取相关方法，不把全部技能说明放进每次提示词 |
| 长任务预算 | 24 次编排模型调用（含摘要）、48 次工具调用、10 分钟任务时限；单工具仍为 60 秒 |
| 大任务进程返回 | 正常完成只发送任务 ID 引用，父进程从本地状态库取回完整记录，避免把大段上下文重复塞进 IPC |
| 纯文本方案 | “只给出方案，不执行”等无文件交付要求的请求可以直接回答，不再强制导出文件 |

此前已有的流式输出、重复调用保护、只读分析、输入快照、具体操作审批、成果校验、任务队列和项目管理继续生效。内部计划标记 completed 不构成实际计算或文件操作证据。

## 上下文处理与原文

`Core/ConversationContextManager.cs` 管理面向模型的上下文投影：

- 软阈值为 192K 序列化字符，整段历史摘要输入前缀最多 160K 字符，摘要最多 20,000 字符。
- 单次整理保留最近 3 个完整消息组；assistant 的 tool_calls 与对应 tool 结果作为整体，不从中间切开。
- 当前原始用户请求被保留。摘要以明确标记的参考数据呈现，不提升为系统指令或文件操作授权。
- 原始 `TaskRecord.Messages` 不被摘要覆盖，先前任务记录仍保留。摘要失败、返回工具调用、超长或不能缩小上下文时明确停止，不使用截断摘要继续。
- 硬上限仍为 512K 序列化字符。软阈值是尽力整理触发点；单个过大消息组、模型真实窗口不足等情况仍可能失败。
- 这些是字符保护线，不是精确 token 估计，尚未按每个模型的真实上下文窗口自动调整。
- 摘要会额外调用同一模型，计入模型调用预算和服务端返回的 token 用量，没有新增模型端点。

新增持久化字段：`context_messages`、`context_summary`、`context_compactions`。下一轮优先采用最近成功任务的上下文投影，再追加后续轮次，避免每轮把整段历史再次叠加。中断的工具批次在投影中转为明确的未完成提示，不生成破损工具协议；告警状态也随投影说明。

精确数字、字段映射或出处缺失时，使用 `read_task_history`：

- `section=steps`：原始参数、工具结果与步骤状态。
- `messages`：该轮原始消息。
- `artifacts`：已登记成果及校验信息。
- `summary`：任务请求、结果状态、摘要及错误码。
- `inputs`：输入快照清单，恢复 file_id、相对名称、字节数和摘要的对应关系。

只能读取当前会话中的任务；通过 task ID 校验后才访问记录。返回 `next_char/has_more`，复合 Unicode 字符不会被分页截成半个。历史回查仍受原有保留/清理策略约束，已清理的记录不能凭摘要恢复。摘要可能有损，模型必须回查原始结果后再报告精确事实。

## 任务计划

计划保存在每轮任务自己的 `runtime/task-plan.json`，最多 16 个步骤，状态为 pending / in_progress / completed / cancelled，同时最多一个 in_progress。

使用 `read` 获取 revision，再以 `replace + expected_revision + items` 替换；版本不匹配时拒绝覆盖。计划在不同 Worker 进程间持久化。本轮计划不是文件整理计划，不要求修改原文件审批；也不会自动重放旧任务或拷贝旧文件操作到新任务。

目前沿用对话与执行详情呈现，没有新增独立的可视化计划看板。

## 文档支持范围

- Word：读取 `word/document.xml`，保留段落、文本 run、制表和换行；不包含页眉页脚、批注、图像或嵌入对象。XML 禁止 DTD 和外部解析。
- PDF：使用现有 PdfPig，保留页码标记，最多解析前 200 页并明确是否只覆盖部分文档；不执行 OCR，损坏、加密或不支持的字体结构仍会拒绝。
- 文本：UTF-8/BOM 编码；UTF-8 校验失败后尝试 GB18030 并说明编码范围，拒绝带 NUL 的二进制内容。
- XLSX 继续使用结构化 `preview_table/aggregate_table`，不把压缩包当普通文本读。
- 文本读取最多 100 行/20K 字符，单行超过 16K 字符明确要求拆分或格式化；通过 `next_line/has_more` 继续。
- 搜索每行返回第一处匹配，最多显示 50 条，实际命中行数和更多结果标志另行返回；没有正则或命令执行。
- 单文档正文最多 50 万字符；纯文本 2 MiB，DOCX 压缩包 20 MiB，展开还受现有 64 MiB 限制。PDF 沿用既有大小/页面文本限额。

每页读取目前会重新解析文档，没有跨 Worker 的正文缓存；大文件反复翻页仍有优化空间。

## 进程和兼容性

Host 继续使用本机用户受限命名管道、PID/nonce 校验和 Job Object。新文件工具、计划及历史回查在独立 Worker 执行，技能说明读取在 Host 内进行。文件参数继续要求 file_id，不能绕过输入快照边界。

正常任务使用 `finished-ref` 返回 ID，父进程验证 ID 并加载持久记录；预览仍使用原有小响应。应更新整套程序目录，避免混用新旧 Host 与通信程序集。

项目删除仍只处理分组元数据，不删除原文件、成果或任务。没有重建用户数据库，没有改写默认模型密钥或用户认证配置。旧候选目录未覆盖；未验证旧二进制对新增事件的降级读取。
